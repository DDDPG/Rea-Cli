REAPER coding. REAPER executing. REAPER verifying.

Rea-Cli is a Python library, CLI, and reference environment that plugs into existing agent harnesses. Agents author RPP as project source, Rea-Cli pre-checks and verifies, and REAPER remains the authoritative parser and execution environment.

01 — Workflow

Three steps: author, execute, verify

Agent / Python / CLI → RPP or Lua source → Rea-Cli pre-check → REAPER → saved project / audio → verification

Agents author or modify RPP project source directly — diffable, reviewable, versionable. Before anything runs, Rea-Cli checks syntax and structure offline; untouched text and opaque plugin data are preserved. REAPER remains the authoritative parser.

One-shot isolated execution: reacli exec starts REAPER inside an isolated resource directory, runs the script, and saves a copy without touching the original. Input snapshots, the script, logs, and a proof are kept for review.

Assert tracks, items, and marker properties on the saved project; check duration, silence, clipping, and the dominant frequency of a test tone in rendered PCM WAV. If verification fails, the result doesn't count.

02 — Capabilities

Organized around one task

The agent submits source, Rea-Cli runs it in isolation, then checks the saved project and rendered audio. It is the pre-check and verification layer; it does not replace REAPER's parser, project semantics, or execution environment.

RPP as source

RPP is treated as project source: agents author or modify it directly, and Rea-Cli provides pre-checks, queries, and semantic diffs; untouched text and opaque plugin data are preserved.

−  NAME "Vocal"
+  NAME "Vocal-Lead"
reacli rpp diff before.rpp after.rpp

Native Lua still available

Agents can write track, MIDI, effect, send, and marker operations in Lua/ReaScript without waiting for every API to be wrapped as a tool. Only REAPER's native ReaScript API — no SWS or ReaPack required.

-- create.lua · generated by Rea-Cli
local track = reaper.GetTrack(0, 0)
reaper.SetMediaTrackInfo_Value(track, "D_VOL", 10 ^ (-6/20))

Isolated runs, retained evidence

Each run executes in an isolated resource directory; input snapshots, the script, logs, and a proof are retained, and the saved project or rendered audio can be re-verified later. A finished process does not prove the result is correct.

runs/20260917-200900-a1b2/
├─ input.rpp    input snapshot
├─ script.lua   executed script
├─ proof.json   execution proof
└─ reaper.log   full log

03 — Quickstart

Install and try it offline

Python 3.10+. Offline RPP checks need Python only; live execution needs REAPER 7.x on this machine.

The example uses the quickstart resources exported by the CLI above; the Python import package is named rac. run() requires a configured local REAPER.
