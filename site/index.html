REAPER coding. REAPER executing. REAPER verifying.

Rea-Cli 是接入现有 agent harness 的 Python 库、CLI 与参考环境。Agent 把 RPP 当作工程源码来编写，Rea-Cli 负责预检查与验证，REAPER 始终是权威的解析与执行环境。

01 — 工作流

三个步骤，一条可信链路

Agent / Python / CLI → RPP 或 Lua 源码 → Rea-Cli 预检查 → REAPER → 另存工程 / 音频 → 验证

Agent 直接编写或修改 RPP 工程源码——可 diff、可评审、可版本化。写入前，Rea-Cli 离线预检查语法与结构；未触碰的文本与插件数据原样保留。REAPER 仍是权威解析器。

02 — 能力

为 agent 回合而设计

源码进，隔离执行，产物与验证出。Rea-Cli 是预检查与验证层，不替代 REAPER 的解析器、工程语义或执行环境。

RPP 即源码

RPP 被当作工程源码对待：agent 直接编写或修改，Rea-Cli 提供预检查、查询与语义 diff；未触碰的文本与不透明的插件数据原样保留。

−  NAME "Vocal"
+  NAME "Vocal-Lead"
reacli rpp diff before.rpp after.rpp

原生 Lua 扩展

保留 Lua/ReaScript 作为逃生舱：轨道、MIDI、效果、发送与标记等宿主原生操作都可由 agent 编写，无需等待每个 API 被封装成工具。仅依赖 REAPER 原生 ReaScript API——不需要 SWS 或 ReaPack。

-- create.lua · 由 Rea-Cli 生成
local track = reaper.GetTrack(0, 0)
reaper.SetMediaTrackInfo_Value(track, "D_VOL", 10 ^ (-6/20))

隔离执行，证据留存

每次运行在独立资源目录中进行，输入快照、脚本、日志与 proof 一并留存；另存的工程与渲染音频可随时再验证。进程结束不等于结果符合要求。

runs/20260917-200900-a1b2/
├─ input.rpp    输入快照
├─ script.lua   执行脚本
├─ proof.json   执行证明
└─ reaper.log   完整日志

接入现有 Agent

Python 库、CLI 与仓库 skill 可直接接入 Claude Code、Codex、Qwen Code 等现有 harness——安装项目级 CLI 工具包与 skill 即可，无需 MCP 常驻服务。

03 — 快速开始

五分钟，跑通第一条链路

Python 3.10+。离线 RPP 检查只需要 Python；实时执行需要本机 REAPER 7.x。

示例使用上方 CLI 导出的 quickstart 资源；Python 导入包名为 rac。run() 需本机已配置 REAPER。

环境要求

Lua 5.3 / 5.4 luac CLI 生成 Lua 的语法预检
SWS / ReaPack / MCP 无需安装
Windows 仅离线检查；执行尚未实现
